## How to read these numbers (caveats)

- The dataset and the matcher were written by the same author in the same session. The dataset
  was committed first and the holdout split was not used for tuning, but the holdout uses the same
  vocabulary and command families as the dev split. **It is not a measure of real users.**
- A better signal is the independent paraphrase probe (`tests/nlu_eval/paraphrases.jsonl`, 40 new
  phrasings, never used for tuning): **20 correct, 20 deferred to the LLM, 0 confidently wrong.**
  So the local fast path is precise but covers about half of unseen phrasing; the Groq planner has
  to carry the rest.
- `pipeline` and `llm` modes were **not run**: no `GROQ_API_KEY` in this environment. Groq's
  acceptance of the generated strict schema is unverified until that run.
- The two items the local matcher defers by design are e-mails whose subject/body must be drafted
  (`en-067`, `roman_ur-071`); they count as wrong in local mode.
- Next step for a trustworthy number: add 100+ real transcripts from the Windows PC (Whisper output)
  to a third split and run `--mode pipeline`.
